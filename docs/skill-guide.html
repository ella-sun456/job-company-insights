JD 需求拆解生成 Skill — job-company-insights

一份可直接分享给其他 AI Agent / 运行时使用的面试调研技能说明。 配套安装包：job-company-insights.skill（标准技能包，可直接安装）。

English overview （中文详版见下文，结构与英文一致）

job-company-insights turns one job description into a two-tab HTML dossier: the role decoded, your fit scored, and the company researched from registration data to business model. Input: the JD (screenshot, link or text) + a company name, optionally a résumé.

  • Tab 1 — JD decode & fit: the five questions a senior HR would ask, a one-line persona profile, a line-by-line decode table (blue = stated, yellow = inferred), a 100-point score across four dimensions, a gap list and a tailored self-introduction.
  • Tab 2 — company research: fundamentals, founder profile, business model, product and business-line matrix, competitors, unstated needs, three opportunities and three risks.
  • Non-negotiables: primary sources first and "unconfirmed" instead of invented numbers; stated vs inferred always colour-coded; no fit score without a résumé.
  • Output: one self-contained HTML file with a download button — openable offline, no server needed.

Install: import install/job-company-insights.zip in WorkBuddy, or copy SKILL.md + references/ + assets/ into your agent's skills folder. Usage: Use job-company-insights to analyze this JD: [JD], company: [name]. Module-by-module data schema: references/html-spec.md; bilingual overview: README.

一、技能定位

项 内容
角色 资深商业尽调分析师 + 前端可视化专家
输入 目标岗位 JD（截图 / 链接 / 文字）+ 公司名称（可选附简历）
输出 单文件、高保真、双 Tab 的 HTML JD 需求拆解全景报告（JD 透视与匹配 / 深度调研看板）
适用 求职面试准备、岗位与公司调研、候选人匹配度评估

核心原则：真实优先、防幻觉、信息分离（事实 vs 推测）、纯代码输出。

一句话说清：它不是把 JD 关键词复述一遍，而是把招聘方视角（HR 五问、真实意图解码、目标人才画像）和候选人视角（匹配度、差距、面试打法）放进同一份报告里。

二、自动触发规则（核心行为）

  1. JD 图 / 链接即触发调研 只要用户发送了 JD 截图（图片）或 JD 链接，立即自动调用调研能力去查公司信息、近期动向与工商事实，无需用户额外指令。未给公司名时，优先从截图 / 链接中识别公司名；无法识别再追问。

  2. 综合匹配度百分制：有简历才打分，没简历不打分 系统自动识别 JD 与简历是否齐备，无需用户指令： - 情况一：JD + 简历都已上传 → 系统自动识别到两者都有，直接走匹配度分析流程，不反问：

    1. 头部「综合匹配度」卡输出百分制总分（如 82/100）；
    2. 在「逐条匹配分析」下方生成 📊 综合匹配度维度拆解：按 经验 / 技能 / 行业认知 / 岗位层级 四维度各给分（权重合计 100），列适配点（绿框）与差距点（红框）；
    3. 全程不反问，直接给结果。 - 情况二：只收到 JD、没有简历 → 系统识别到缺简历，不要硬做匹配度评分，而是先用大白话反问：

      「收到岗位信息了。如果你把简历也传上来，我可以帮你算一个匹配度分数，明确哪些地方你够格、哪些还差一点。光看 JD 的话，只能帮你拆解岗位要求，没法对比你自身的情况——要不要补一份简历？」 - 用户补了简历 → 立刻走情况一完整流程； - 用户不补 → 只做 JD 拆解（岗位要求、硬性门槛、潜在考察点），不给任何匹配度分数；综合匹配度卡、维度拆解、简历依据列、适配/差距点统一标 待补充 / 待评估。 - 核心原则：有简历才有匹配度分数，没简历就不打分；提示语用大白话；缺信息先问再干，不瞎猜。

三、约束红线

  1. 防幻觉：优先使用一手来源（工商信息 / 官网 / 应用商店 / LinkedIn / 权威新闻）。找不到可靠来源直接写「无法确认」，绝不编造任何数字或履历。
  2. 信息分离：JD 拆解必须区分「JD 明确写出」(蓝) 与「合理推测」(黄)；公司调研必须区分「事实」(蓝·工商) 与「推测」(黄)。
  3. 纯代码输出：除开头简短说明外，最终输出必须是完整单文件 HTML（<!DOCTYPE html> + <style> + <script>），无外部依赖（不引 CDN、外部字体 / 图片）。JD 截图以 data:image/...;base64,... 内嵌保持单文件。
  4. 标题动态化：<h1> 必须是 【公司名称】 - 【岗位名称】JD 需求拆解全景报告（无序号、无括号）。
  5. 排版极简：标题中禁止「一、二、零」等序号，禁止中文 / 英文括号 () （）。
  6. JD 图 / 链接即触发调研（见第二节）。
  7. 综合匹配度百分制：有简历才打分（见第二节，两情况逻辑 + 大白话反问）。

四、输出规范

  • 单文件 HTML：全部样式与脚本内联，可双击打开，便于分享。
  • 顶部 Header：灰白渐变，含动态标题、标签行（赛道 / 行业 / 模式 / 阶段）、4 个数据卡片：公司阶段 / 核心赛道 / 综合匹配度(百分制) / 风险等级。
  • 双 Tab：页签文字「JD 透视与匹配」「深度调研看板」，JS switchTab(event, id) 无刷新切换，无序号无括号。
  • 标签体系：.tag.fact(蓝=事实·工商/JD明确) / .tag.infer(黄=合理推测)。
  • 高亮框：绿(结论) / 黄(策略) / 红(风险) / 蓝(反问)，均 border-left:4px solid。
  • 表格：.matrix-table，表头浅灰、单元格竖线。

五、工作流与模块结构

Tab 1 — JD 透视与匹配

# 模块 要点
1 JD 原文截图 左侧卡片，base64 内嵌，点击放大
2 资深 HR 视角五问 右侧卡片（grid-2 左右双排）：岗位干什么 / 职责能力特质(蓝JD·黄推测) / 上下游协作图 .role-map / 需准备的真实案例
3 HR 终局判断 该岗位真正想要的人画像
4 JD 深度解码：他们到底要什么人 1 句话 archetype + grid-2 两栏「🔧 硬门槛 / 🧠 软特质」+ .chips 核心特质与隐藏期待
5 JD 逐条拆解 .matrix-table：原文摘句 / 类型(硬性·软性·加分) / 解码：他到底要什么 / 标注(蓝JD明确·黄推测)
6 逐条匹配分析 + 维度拆解 表头 JD要求 / 简历依据 / 匹配度 / gap·风险 / 面试具体策略；表下 📊 综合匹配度维度拆解（经验/技能/行业认知/岗位层级 四维度各给分，权重合计 100，附适配点绿框 + 差距点红框）。无简历则不打分、统一标「待补充 / 待评估」
7 定制版自我介绍 ≤250 字填空区
8 Gap 清单 红 / 黄 / 绿 + checkbox + 补课建议
9 面经总结、真题预测与面试行动指南 单卡 5 子块：📚 面经总结与真题预测 · ✅ 面试前准备清单 · 🌙 面试前 1 天必做 · 🎯 面试中关键原则(.chips) · 🎒 面试当天的准备

Tab 2 — 深度调研看板

# 模块 要点
1 公司基本面 .info-grid（全称&成立 / 赛道&背景 / 模式 / 人员规模，工商项标「事实·工商」）+ 卡片内「🎯 近期重点方向（推测）」子块（业务 / 市场 / 组织 + .hl-yellow 与岗位匹配度）。生命周期 / 融资 / 营收并入 info-grid 子注
2 创始人画像 姓名行(事实+推测标签) + .ftl 时间线（背景旅程 / 关键转折·低谷逆袭）+ .chips 价值观 + .mini-stat 托底；无法确认项如实标注，低谷缺失转面试反问
3 商业模式 .grid-2 两卡：盈利逻辑 | 大客户依赖风险(高则 .hl-red)
4 产品与业务线 核心 / 主力 / 利润 / 引流 矩阵（每行列一句简注）+ .hl-blue「岗位业务线地位」+「📌 主推产品」数据驱动占位（产品/品类/场景·主推定位与打法·渠道·核心卖点）。分类维度不写死电商口径
5 竞品分析 直接 / 间接 / 潜在威胁 优劣势矩阵
6 隐藏需求与岗位差异 .hl-blue 真实痛点反推 / 同行差异 / 未写明看重 + .hl-yellow 面试可反问问题
7 结论建议 .hl-green 三句话总结 + 机会 / 风险两栏 + 面试展示重点虚线框

调研优先（Research-First Mandate）

  • 收到 JD + 公司名后先解析 JD（逐条区分明确 vs 推测），再用一手来源真实调研公司。
  • 所有占位必须换成真实内容；无法确认写「无法确认 / 公开信息未披露」，严禁把模板占位或编造数字当成品。
  • 工商九项红线（成立时间 / 法人 / 注册资本 / 社保人数 / 融资 / 年销售额 / 核心赛道 / 资质 / 工作制）严格标注来源；缺失只标「需面试确认 / 公开信息未披露」。

将 job-company-insights.skill 交给支持该格式的 AI 运行时 / 技能市场直接安装。

方式二：手动放置

将技能目录放到用户级技能路径：

├── references/
│   └── html-spec.md

AI 在对话中识别到「JD + 公司名 / 面试截图」即按本规范自动调用。

文件结构说明

  • SKILL.md：角色定义、约束红线、工作流、调研优先指令、初始化话术。
  • references/html-spec.md：强制 CSS 规范 + 逐模块数据 schema（颜色 token、高亮框、标签、可视化组件）。
  • assets/template.html：完整可运行骨架，含 Header / 双 Tab / 各模块占位与切换脚本。

七、可移植 / 分享说明（发给其他 AI）

本技能以标准 .skill 包形式封装，可直接发给其他支持该格式的 AI Agent 运行时安装复用；配套这份说明文档也可整段贴入任意 AI 对话，由其按规范重建技能或直接调用。

移植时必须保留的三条底线，确保跨 AI 不失真： 1. 防幻觉与一手来源优先——无来源即「无法确认」，不编造。 2. 信息分离——事实(蓝) 与 推测(黄) 必须区分标注。 3. 行为约束——JD 图/链接自动触发调研；面试截图先判简历（百分制匹配度仅在有简历时给出）。

初始化话术：「你好，我是您的面试调研专家。请发送【目标岗位 JD】和【公司名称】，我将为您生成高保真的 HTML JD 需求拆解全景报告。」
